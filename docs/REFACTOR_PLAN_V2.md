# GeoQuest V2 重构方案

日期：2026-09-16。范围：精选选题、AI 审核流程、一个完整示范主题；本轮不部署线上网站。

## 1. 先把一个主题做好

从“66 个候选、10 个 MVP、六个入口”收敛到四个探究方向。首页先展示一个可操作的地形实验，其余方向作为后续计划。旧代码和 Excel 保留，六个待融合或暂缓主题移出活动目录，不把未完成内容包装为精品。

问题不只是配色。现有产品层次和审核流程先于模型成熟，视觉装饰占据空间，而模型和证据不足：

- 旧地形主题已有解析式高程与剖面，但主要使用平面 Canvas；风险分混入预置沟谷、通视判断和权重。
- 地球主题的部分开关只影响文字，模型反馈不完整，季节标签边界需要修复。
- 农业主题中，部分适宜度计算只取决于区域，没有真正响应作物选择。
- 人口主题以三个硬编码地区代替空间分布，缺正式数据支撑。
- 生产编译器原先统一引用旧 interactives，开发模式的 redesign 成果不能自动进入生产版本。

重构的基本单位是一个能回答问题的模型。每个主题优先保证“改变量 → 模型变化 → 读证据 → 解释差异”，再增加任务包装。

融合的是探究链和底层模型，不把多个 MVP 的面板直接拼在一个页面。一个阶段只有一个主操作对象。选题不再追求原型、卷册或入口全覆盖。

## 3. 开源项目如何用

已读取用户提供的[开源调研页](https://4kz7pdxnna7qs.aiforce.cloud/app/app_17e54wb10a5/)。页面的 Star 和更新时间是候选检索信息，本方案不以它们代替代码、许可和适配判断。以下依据项目官方仓库核对；不批量复制榜单项目。

| 项目 | 能带来的改进 | 复用方式与决定 |
| --- | --- | --- |
| [Stellarium Web Engine](https://github.com/Stellarium/stellarium-web-engine) | WebGL 星空、天空图层、大气与天体展示 | 用户清单中最值得做后续技术验证的引擎。AGPL-3.0；原生构建涉及 Emscripten / SCons / WASM，星表和纹理需要逐项确定离线范围与许可。适合天空观测，不能直接替代地球日照/四季教学模型。本轮未接入 |
| [Magrit](https://github.com/riatelab/magrit) | 浏览器内的专题地图、符号化、分级与统计表达 | GPL-3.0-or-later。借鉴选变量—选表达—读图例的交互，后续可独立部署或按许可复用代码。它是一套应用，整站嵌入不是轻量组件。本轮未引入其代码、底图和数据 |
| [H5P Standalone](https://github.com/tunapanda/h5p-standalone) | 自托管已有互动课件，无需 H5P 服务器 | 播放器 MIT。有合适课件时再接入；课件与内容类型库分别核对许可，本地打包，不启用成绩上报。它不负责三维地理模型。本轮未接入 |
| [GeoGuess](https://github.com/GeoGuess/GeoGuess) 等街景猜位游戏 | 依据视觉线索提出区位假设 | GeoGuess 为 MIT，核心依赖 Google Street View，并包含联机体系；本项目借鉴“线索—假设—验证”玩法，不把街景外链作为核心离线课程 |
| [Marble](https://github.com/KDE/marble)、桌面 Stellarium、LMS 类 | 独立桌面或完整教学平台 | 不是可直接装进 React 页面的教学组件。保留参考，不为一个模型引入账号、后台或整个平台 |
| 教材聚合、行政区数据仓库 | 能发现候选资料 | 仓库可访问不等于所含教材和地图可再发布。没有明确素材来源与适用授权时不复制 |

首个示范补充采用两个成熟的底层开源库（不是榜单中现成课件的移植）：

- [Three.js](https://github.com/mrdoob/three.js)，本次安装 0.186.0，MIT：复用 WebGL 渲染、网格/材质、OrbitControls 的旋转缩放和资源管理。
- [d3-contour](https://github.com/d3/d3-contour)，本次安装 4.0.2，ISC：复用成熟的等值线生成，避免继续维护自行编写的 marching-squares 查表。普通 ECharts 图表不能解决这个高程等值线几何问题，因此这里采用 D3。

两者通过 pnpm 锁版本，自托管，无远程 CDN、在线地形服务和下载纹理。山地高程与教学任务原创，保留第三方许可文本。复用范围是渲染、控制器和算法；教学模型仍需要我们定义和验证。

## 4. Excel 只负责选题

旧 V1.1 工作簿含 11 张表，主题矩阵扩展到 BI 列（61 列）。它把选题、教材定位、评分、资产、审核和排期合在一起，维护成本过高。

新版只保留一张“精选选题”表、五条记录（四个方向加一个暂缓项）、八列：选题 ID、主题、整合原主题、核心问题、主要互动与证据、开源复用方向、安排、当前进展。不再填写人工审核人、评分权重、课标页码和多层状态。

Excel 不驱动发布。内容和模型保存在代码仓库，审核结果在单份报告中，旧矩阵作为历史材料保留。后续新增选题先写一个可探究问题和一项证据产出，不能只填一个展示模型名称。

## 5. 审核简化为一次 AI 审查和一组自动检查

取消八类人工签字和专家打分。由开发环境中的 AI 读取改动、核对来源、审查模型、运行测试并查看浏览器，形成一份版本对应的报告。网页不增加 AI 接口，也不把学生内容发送给模型。

最短流程：

1. AI 完成实现和自检；涉及数值时核对独立预期，例如直线距离、反向爬升恒等式、等高线标高误差。
2. AI 查看探索、课堂和手机端实际画面，操作关键控件，记录错误和修复。不能以截图文件存在或“构建成功”冒充已审查。
3. 一份 `aiReview` 记录保存状态、AI 标识、日期、主题版本及报告路径；发布校验要求与当前版本相符、报告存在且非空。
4. 自动执行内容、类型、lint、单元测试、构建、公开边界检查；浏览器交互测试纳入常规验证。通过的主题才进入生产构建。

`pnpm verify` 运行自动检查，不会自行调用大模型；AI 审查由 Codex 开发任务完成。未来如确有无人值守需求，再把同一审查提示接入 CI，不为本次示范新建模型服务。程序不批量填写 passed，不把未知来源自动改为已授权。AI 负责核对许可与适用范围，不能创造素材授权或法定审图许可；无法确认的素材直接换用明确可用的资产或原创示意。

旧 manifest 的 `reviews` 暂时保留兼容，已不再承担发布判定。迁移无需先清理全部历史 YAML。修改主题内容时须同步升级版本并重新审查；当前版本绑定不是文件签名，仍依赖开发流程保持版本诚实，后续可按实际需要增加内容摘要绑定。

## 6. 本轮示范的实现与验收

入口沿用 `/topics/contour-rescue`，课堂入口为同地址附加 `?mode=classroom`。

- 一份原创高程函数，121 × 91 采样网格，派生真实三维地形和 D3 等高线。
- 三条同起终点路线。直达线与折返线形成距离、爬升和坡度的取舍，不提供虚构安全评分。
- 路线选择、观察进度与三维白点、二维白点、高程剖面同步；旋转、俯视、切片、50/100/200 m 等高距和 1/1.5/2 倍垂直夸张。
- 记录多条路线，导出结构化 CSV。页面刷新清除证据，不收集身份和自由文本。
- 垂直夸张只改变渲染，数值按原始地形计算；切片不是洪水淹没图；无 WebGL 时保留等高线与计算操作。
- Three.js 仅在主题路由加载；渲染按变化触发，不持续空转；退出时释放几何体、材质、控制器和 renderer。
- 旧手帐图片不用于新首页和地形页，未核清的候选图片不进入当前生产包。

本轮验收关注模型同源、数值正确、控件真实生效、键盘替代、移动端不溢出、课堂可读、断网后核心操作可用、生产路由确实加载新版。测试结果与限制见对应 AI 审查记录。

## 7. 后续顺序

先用本轮地形主题验证视觉和课堂体验，再决定是否按此方式改造地球主题。每完成一个方向才扩充首页，不同时重写所有主题。地球主题先验证光照、自转和天球视角；水土主题先建立有局限说明的过程模型；农业主题先补足作物输入与气候条件对结果的真实影响。需要地图或遥感时才引入对应数据适配器，不提前扩成地理平台。

## 8. 2026-09-17：第二个主题完成

“地球与太阳”已按 20 分钟课堂脚本重建为“预测—跟随一天—比较一年—证据解释”。三维地表点、自转光照、太阳高度与昼长共用球面几何；用同纬度南北半球和零倾角实验控制变量。旧通用外壳和文字型方向开关不再用于该入口。

沿用 `/topics/earth-motion-lab`，探索与课堂共用状态；首页增加第二个可操作实验。复用已安装的 Three.js / OrbitControls，没有引入星空平台、外部课程接口或地图素材。来源、课堂问题、修复与验证边界见 [AI 教学模拟报告](reviews/earth-sun-v2.md)。本次完成本地生产构建，未部署线上；后续优先处理水土与流域的过程模型。

## 9. 2026-09-17：第三个主题完成

“水土与流域”沿用 `/topics/loess-soil-water`，按“预测—坡面对照—流域调蓄—证据解释”串起坡面水土保持和下游流量。以共同雨型、两种覆盖和有限滞蓄空间做受控比较；逐时段保持水量守恒，显式区分流量峰值、累计产流、暂存和相对侵蚀。

本次融合的是坡面到流域的探究链，未声称已经实现真实流域泥沙输送、湖泊生态恢复或长江调度。无量纲侵蚀假设不再包装为实际流失量，不再用完成四轮按钮代替保存证据。新图形为原创 SVG，不增加地图、外部引擎或接口。首页开放第三个入口，后续方向保留气候与农业。详见 [AI 教学模拟与审查](reviews/watershed-v2.md)。

## 10. 2026-09-19：农业与人口主题重构

按本轮要求完成两条独立的20分钟课堂探究。气候与农业以原创季节水量模型替换未经数据支撑的真实气候基线，操作雨季、播期、作物及有限补灌；人口与区域从暂缓重新纳入，采用World Bank四国2023人口和陆地面积最小快照，先比较总量与密度，再做面积加权的统计尺度实验。人口主题不以统计格冒充地图，不从四国样本推出人口因果规律。

五个主题各有独立问题链、可回看导出的真实操作证据和模型边界；新两主题无需新增依赖、外部教学API或WebGL。延续AI审查加确定性检查，审核通过仅意味着纳入本地生产构建。本次未部署、提交或推送。详见[农业模拟教学报告](reviews/agriculture-v2.md)和[人口模拟教学报告](reviews/population-v2.md)。本节更新前述暂缓安排，历史矩阵未在本轮另行编辑。
