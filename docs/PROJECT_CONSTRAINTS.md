# GeoQuest 项目约束

> 文档状态：V1.1
> 生效日期：2026-08-09
> 适用范围：GeoQuest · 地理智探 V1 及其初中地理互动主题
> 约束地位：本文件是 V1 的唯一项目约束源。主题策划、内容制作、设计、开发、审核与发布均不得另行维护相互冲突的规则副本。

V1.1 变更说明：统一“探索模式”术语；区分产品入口与交互原型；建立内部记录、公开源文件和浏览器清单的脱敏投影；把事实参考、数据集、地图、媒体和原创模拟分型；要求审核状态必须绑定人工证据；澄清 350 KB 为首页初始应用 JavaScript 预算。现有隐私、地图、版权和 V1 非目标没有放宽。

## 1. 项目定义

### 1.1 项目愿景

GeoQuest 是一个“教材驱动的地理互动探索平台”。它不把教材扫描页搬到网页，而是从教材正文、活动、地图、图表和案例中提炼适合观察、比较、模拟、推理和决策的核心问题，将其设计成可在课堂投屏、也可由学生在课后自主探索的公开主题页面。

项目追求的不是主题数量，而是让学生通过可核对的地理证据完成一次有意义的思考：

> 核心问题 → 主要互动 → 证据产出 → 解释反思

### 1.2 目标用户

- 主要用户：七、八年级学生。
- 课堂使用者：初中地理教师。
- 内容维护者：GeoQuest 项目内容、设计与开发人员。
- 审核者：教学、地图、数据、版权、隐私和技术质量审核人员；同一人可承担多个角色，但门禁不得省略。

### 1.3 两种使用模式

1. 探索模式：面向学生课后自主探索，保留完整引导、操作说明、来源和反思。
2. 课堂模式：面向教师公开投屏，通过同一地址附加 `?mode=classroom` 启用大字号、低控件密度、重点步骤和全屏展示。

两种模式必须使用同一份主题内容、同一 `TopicManifest` 和同一数据快照，不维护两套页面或两套教材映射。课堂模式不是教师后台，不包含账号、权限、班级或学习记录。

主题统一地址：

```text
/topics/:slug
/topics/:slug?mode=classroom
```

## 2. V1 目标与非目标

### 2.1 V1 目标

- 建立稳定、可持续维护的教材单元与主题映射。
- 形成八类互动原型和一组可复用组件。
- 建立教材探索、地图实验室、数据实验室、地球实验室、区域探索、地理挑战六个稳定产品入口；产品入口与互动原型是两个不同维度。
- 让每个已发布主题同时适用于课堂展示和课后探索。
- 在校园网络不稳定、外部服务失败时仍能完成核心学习流程。
- 通过结构化证据产出呈现学生的观察、比较、判断或方案。
- 从一开始建立教材引用、课标引用、数据来源、版权和地图合规门禁。

### 2.2 V1 非目标

V1 不建设下列能力：

- 学生账号、教师账号、注册、登录、单点登录或身份认证。
- 班级、作业、成绩、排行榜、讨论区、评论区或学习管理系统。
- 教师管理后台、认证后台或动态内容管理后台。
- 云端学习记录、跨设备同步、学生画像或个性化推荐。
- AI 聊天机器人、生成式 AI 接口、自动问答、自动批改或生成式内容。
- 实时协作、师生消息、站内信或通知系统。
- 访问统计、埋点、热力图、A/B 测试、广告或第三方追踪。
- Cookie、本地广告标识、设备指纹或跨站识别。
- 三维地球、三维城市、VR/AR 或需要高性能图形硬件的引擎。
- 以实时新闻、实时气象或实时灾情接口作为核心课程内容。
- 公开展示教材扫描页、电子教材或大段教材原文。

## 3. 绝对禁止项

下列约束属于 V1 红线，不得通过“可选功能”“仅教师使用”“匿名统计”或“以后再处理”等方式绕过：

1. 不得创建学生或教师账号。
2. 不得建设认证、授权或账号后台。
3. 不得将学习过程、完成状态或答案上传云端。
4. 不得接入 AI 聊天机器人或任何生成式 AI 接口。
5. 不得部署访问统计、行为分析、广告、Cookie 或第三方追踪脚本。
6. 不得保存姓名、学号、学校、班级、联系方式、自由文本答案、精细位置或设备标识。
7. 不得让核心课程依赖实时外部接口。
8. 不得公开转载教材扫描页、教材插图或大段正文。
9. 不得使用来源、许可或地图合规状态不清楚的素材进入发布状态。

任何需要解除上述红线的需求，都必须先升级项目大版本、重新完成未成年人隐私和合规评估，并修改本文件；不能通过单个主题的例外处理。

## 4. 教材、课标与主题范围

### 4.1 稳定单元编号

教材单元使用稳定编号：

```text
G7A-C01-S01  # 七年级上册、第一章、第一节
G7A-C01-P01  # 七年级上册、第一章、探究与实践
```

卷册枚举固定为：

```text
G7A | G7B | G8A | G8B
```

开发结论固定为且只能为以下四种之一：

```text
独立开发 | 融合开发 | 复用已有主题 | 暂不单列
```

- `独立开发`：该单元形成一个唯一主题。
- `融合开发`：该单元内容并入另一个主题，必须记录目标主题 ID 和融合理由。
- `复用已有主题`：沿用既有主题的核心交互与组件，只替换情境或数据，必须记录目标主题 ID 和复用理由。
- `暂不单列`：不形成独立主题，必须说明内容承载位置和不单列理由。

### 4.2 主题 ID 与 slug

- 主题 ID 使用 `GQ-T001` 形式，发布后永久稳定，不因标题修改而重编号。
- slug 使用小写英文、数字和短横线，发布后原则上不变。
- 如必须修改 slug，旧地址必须保留静态重定向。
- 同一主题可以关联多个教材单元，但只能有一个核心问题和一个主要操作对象。

### 4.3 引用要求

教材引用必须记录：

- 文件名。
- 教材单元 ID。
- 书内起止页。
- PDF 起止页。
- 是否完成原始页面视觉核对。

课标引用必须记录：

- `standardId`。
- 文件名。
- PDF 页码。
- 印刷页码。
- 所属“内容要求 / 学业要求 / 教学提示 / 学业质量 / 实施建议”位置。

OCR 只能用于检索和初步整理，不能作为未经原图核对的最终证据。

上述教材与课标定位只保存在内部规划、制作和审核记录中。公开仓库、公开主题清单、浏览器数据和构建产物不得出现教材源文件名、教材或课标 PDF 页码、内部证据路径及本机路径；公开页面只呈现经脱敏的单元名称、课标要点和来源说明。

## 5. 教学设计硬约束

### 5.1 四段式主题契约

每个主题必须完整具备：

1. 核心问题：可以探究、可以形成不同假设，且能用地理证据回答。
2. 主要互动：学生围绕唯一主操作对象执行一个连贯操作。
3. 证据产出：形成可核对的地图、图表、对比表、标注、路线、情景结果或方案卡。
4. 解释反思：提示证据的适用范围、不确定性、替代解释或人地关系取舍。

缺少任一项，不得进入“待审核”状态。

### 5.2 一个主操作对象

每个主题只能设置一个主要操作对象，例如一张主地图、一个时间轴、一个变量模型、一组对照对象或一个决策面板。

- 辅助图表可以跟随主对象变化，但不能形成第二套独立玩法。
- 课堂主流程应在 8—15 分钟内完成。
- 课后完整探索建议控制在 15—25 分钟。
- 一个页面不同时堆叠地图、时间轴、模拟器、测验和长篇叙事五套交互。

### 5.3 八类互动原型

```text
map-explorer  地图探索     story-map      时空故事
simulator     变量模拟     data-explorer  数据探索
compare       区域比较     decision-lab   决策模拟
image-explorer 遥感对比    geo-challenge  地理挑战
```

代码和内容文件使用左侧稳定键，界面使用右侧中文标签。每个主题只能选择一个主原型。D3 不能被定义为单独原型。旧版“时间演变、数据探究、对比实验、决策实验、图像解读”等标签迁移到上述稳定键，不再作为接口枚举。

### 5.4 证据和反思的隐私边界

- 证据产出优先使用结构化选择、数值、标注、排序、路线或方案。
- 反思问题可以引导学生口头表达、课堂讨论或纸笔记录。
- 网站不得持久化自由文本答案。
- 本地导出的证据卡不得自动加入姓名、学校、班级、位置或设备信息。

### 5.5 双模式一致性

课堂模式只能改变展示，不得改变教学事实、证据口径或答案逻辑：

- 可放大字号、图例和关键标注。
- 可减少非核心控件。
- 可提供教师控制的“下一步”。
- 不得隐藏来源、审图号和关键风险提示。
- 不得出现仅登录教师才能访问的内容。

## 6. 技术基线

### 6.1 固定技术栈

- UI：React。
- 语言：TypeScript，开启严格模式。
- 构建：Vite。
- 路由：React Router。
- 内容：MDX 与 YAML；主题元数据最终编译为类型安全的 `TopicManifest`。
- 常规图表：ECharts。
- 地图：MapLibre，通过 `MapProviderAdapter` 适配天地图、本地合规瓦片或静态地图。
- 定制交互：仅当 ECharts 无法合理实现时才使用 D3，并记录采用理由。
- V1 不引入 Cesium、Three.js、Deck.gl 三维模式或其他三维地球引擎。

### 6.2 架构边界

- V1 为公开静态站点，不需要应用服务器或业务数据库。
- 不建设账号服务、鉴权服务、云函数、学生数据 API 或管理后台。
- 主题内容在构建阶段完成校验；浏览器运行时不远程拉取 MDX 或 YAML。
- 每个主题按路由懒加载组件和数据。
- React Router 的深链接由静态托管回退规则或预生成入口保证可访问。
- 所有地图提供商必须经适配层使用，主题组件不得直接写死第三方瓦片 URL。

### 6.3 依赖控制

- 依赖必须有明确用途、维护状态和许可。
- 禁止仅为一个简单动画引入大型框架。
- ECharts 可以完成的常规图表不得转用 D3 重写。
- 新增运行时第三方脚本必须先证明不会产生追踪、Cookie 或外部单点故障。
- 生产环境不得依赖公共 CDN；脚本、样式、字体和关键素材全部自托管。

## 7. 静态优先与数据策略

### 7.1 核心原则

核心课程必须在 GeoQuest 站点自身可用时完成，不能把外部 API 的在线状态当作教学条件。

- 数据、字体、图标和关键素材自托管。
- 实时数据必须同时提供带日期的本地快照。
- 页面默认先加载本地快照，外部数据只可作为明确标注的可选更新。
- 外部请求失败时，主题自动退回本地快照，不阻断核心流程。
- 教师进入课堂模式时，不发起非必要外部请求。

### 7.2 外部数据集快照最小元数据

每个 `dataset` 来源的快照至少记录：

```yaml
kind: dataset
id: DS-...
title: ...
url: https://...
version: ...
retrievedAt: YYYY-MM-DD
timeCoverage: ...
spatialCoverage: ...
license: ...
attribution: ...
snapshotPath: ...
processing:
  - ...
checksum: sha256:...
review:
  status: unreviewed
```

事实参考、地图、媒体和原创模拟不伪装成数据集快照，分别按第 8 节的来源类型记录。原创模拟必须说明方法、版本、参数和局限；事实参考必须记录可核验网址和核验日期。

### 7.3 数据最小化

- 只保留回答核心问题所需字段、时间和空间范围。
- 大型栅格和矢量数据应在构建阶段裁剪、概化、降采样。
- 浏览器不得下载整景遥感数据或全国高精度原始数据。
- 每个数据加工步骤必须可重复，并保留版本和参数。
- 教学示例数据必须清楚标记“示例 / 模拟 / 实测”，不得混淆。

### 7.4 外部数据降级

每个使用外部数据的主题必须定义：

1. 本地快照。
2. 快照日期。
3. 失败提示。
4. 不依赖外部数据的核心结论路径。
5. 数据过期时的人工更新流程。

## 8. 内容模型与公开投影

内容模型分为四层，禁止把内部制作记录直接当作浏览器接口：

1. `CatalogEntry`：66 个长期候选主题的脱敏目录；V1 只承诺其中 10 个，其他主题保持候选状态。
2. `InternalTopicRecord`：内部教材定位、课标定位、审核人与证据；只存在于不公开的规划与审核空间。
3. `TopicManifestSource`：公开仓库内的 YAML/MDX 主题源文件。
4. `PublicTopicManifest`：构建时生成并交付浏览器的脱敏数据。

工程可以拆分接口，但必须保持以下语义：

```ts
type ProductChannel =
  | "textbook-explorer"
  | "map-lab"
  | "data-lab"
  | "earth-lab"
  | "region-explorer"
  | "geo-challenge";

type TopicPrototype =
  | "simulator"
  | "map-explorer"
  | "story-map"
  | "data-explorer"
  | "image-explorer"
  | "compare"
  | "decision-lab"
  | "geo-challenge";

type ReviewStatus = "unreviewed" | "initial" | "approved" | "blocked";

interface ReviewRecord {
  status: ReviewStatus;
  reviewer?: string;
  checkedAt?: string;
  evidencePath?: string;
  notes?: string;
}

interface SourceBase {
  id: string;
  title: string;
  attribution: string;
  review: ReviewRecord;
}

interface ReferenceSource extends SourceBase {
  kind: "reference";
  publisher: string;
  url: string;
  verifiedAt?: string;
}

interface DatasetSource extends SourceBase {
  kind: "dataset";
  url: string;
  version: string;
  license: string;
  retrievedAt: string;
  timeCoverage: string;
  spatialCoverage: string;
  snapshotPath: string;
  checksum: string;
  processing: string[];
}

interface MapSource extends SourceBase {
  kind: "map";
  assetId: string;
  version: string;
  url: string;
  license: string;
  reviewNumber?: string;
  modified: boolean;
  localAssetPath: string;
}

interface MediaSource extends SourceBase {
  kind: "media";
  creator: string;
  url: string;
  license: string;
  localAssetPath: string;
  modified: boolean;
}

interface SimulationSource extends SourceBase {
  kind: "simulation";
  method: string;
  parameters: string[];
  version: string;
  limitations: string[];
}

type SourceRef =
  | ReferenceSource
  | DatasetSource
  | MapSource
  | MediaSource
  | SimulationSource;

interface TopicManifestSource {
  id: `GQ-T${string}`;
  slug: string;
  title: string;
  summary: string;
  volume: "G7A" | "G7B" | "G8A" | "G8B";
  chapter: string;
  channels: ProductChannel[];
  prototype: TopicPrototype;
  competencies: ("人地协调观" | "综合思维" | "区域认知" | "地理实践力")[];
  coreQuestion: string;
  primaryInteraction: {
    object: string;
    action: string;
    feedback: string;
  };
  evidenceOutput: {
    type: "地图" | "图表" | "对比表" | "标注" | "路线" | "情景结果" | "方案卡";
    description: string;
    persistsFreeText: false;
  };
  reflectionPrompt: string;
  modes: {
    exploration: { path: `/topics/${string}` };
    classroom: { query: "?mode=classroom"; sameContent: true };
  };
  classroomMinutes: number;
  explorationMinutes: number;
  releaseBatch: `Sprint ${1 | 2 | 3 | 4 | 5}` | "backlog";
  hints: string[];
  components: string[];
  sources: SourceRef[];
  reviews: {
    teaching: ReviewRecord;
    curriculum: ReviewRecord;
    textbook: ReviewRecord;
    data: ReviewRecord;
    map: ReviewRecord;
    copyright: ReviewRecord;
    privacy: ReviewRecord;
    technical: ReviewRecord;
  };
  status: "候选" | "已设计" | "开发中" | "待审核" | "已发布" | "已归档";
  version: `${number}.${number}.${number}`;
  updatedAt: string;
}
```

`PublicTopicManifest` 由 `TopicManifestSource` 白名单投影产生，只保留公开页面需要的字段。内部教材源文件、教材或课标 PDF 页码、审核人身份、内部证据路径和本机路径不得进入公开清单或构建产物。公开仓库中的 authoring manifest 如记录审核字段，审核人只能使用公开角色/别名，证据引用必须是仓库相对且可公开的摘要引用；真实身份、私下证据和机器路径仍只存在于 `InternalTopicRecord`。浏览器投影必须删除 `reviewer`、`evidencePath` 和内部备注。

任何 `approved` 记录必须同时有审核人、审核日期和可核对证据。生成器、迁移脚本、测试和开发环境均不得自动把审核状态设为 `approved`；缺少证据时只能保持 `unreviewed`、`initial` 或 `blocked`。

### 8.1 Manifest 校验

构建必须失败于以下情况：

- ID、slug、公开卷册/章节定位缺失，或内部发布记录缺少教材/课标映射。
- 使用了八类原型之外的原型值。
- 产品入口为空或含非枚举值。
- 核心素养为空或含非枚举值。
- 缺少核心问题、主要互动、证据产出或反思。
- `dataset` 缺少许可、版本、本地快照、校验值或加工记录。
- `simulation` 缺少方法、版本、参数或局限。
- 地图主题缺少来源、审图状态或门禁记录。
- 许可不清的数据进入“待审核”或“已发布”。
- `approved` 缺少审核人、日期或证据。
- 公开投影或构建产物含内部定位、本机路径或私有文件名。
- `updatedAt` 或语义版本缺失。

## 9. 内容与版权约束

### 9.1 教材使用边界

- 教材只作为教学分析与引用索引，不作为网站公开素材库。
- 不公开上传教材 PDF。
- 不截取或展示教材扫描页。
- 不直接复制大段教材正文、活动题或解说。
- 不通过重新排版、拼图或模糊处理规避教材版权。
- 教材内容使用原创表述、重新设计的问题和自制图形呈现。
- 对教材页码的引用只用于内部追踪与审核。

### 9.2 素材优先级

1. 原创文字、原创矢量图和原创交互。
2. 政府、国际组织、科研机构和数据发布方的一手开放数据。
3. 许可清晰、可满足公开教育网站使用的素材。
4. 未能确认许可的素材不得进入产品；不能以“教育用途”替代授权核对。

### 9.3 必备记录

每项非原创素材必须记录：

- 标题和作者/机构。
- 原始网址。
- 许可及具体版本。
- 获取日期。
- 是否修改及修改内容。
- 署名方式。
- 本地文件和校验值。
- 是否允许再发布、改编和公开展示。

### 9.4 版权红线

任何下列情况直接阻塞发布：

- 找不到原始来源。
- 许可只允许个人使用或不允许再发布。
- 需要书面授权但尚未取得。
- 图片、地图或视频含第三方版权且未单独确认。
- 计划直接复用教材扫描图。

## 10. 地图合规约束

地图发布门禁依据[《地图管理条例》](https://www.gov.cn/zhengce/zhengceku/2015-12/14/content_10403.htm)和[《地图审核管理规定》](https://www.beijing.gov.cn/zhengce/zhengcefagui/qtwj/201712/t20171206_1162174.html)建立，并同时遵守现行公开地图内容表示规范。

### 10.1 选源原则

- 优先直接使用具有审图号的公益性或合规地图。
- 中国疆域、行政区、港澳台、南海诸岛、钓鱼岛及其附属岛屿等内容优先使用自然资源部标准地图或权威合规服务。
- 保留地图名称、来源、版本、审图号、下载日期和原始文件。
- MapLibre 只是渲染器，不会自动使地图合规。
- Natural Earth、OpenStreetMap 或其他境外地图数据的开放许可不等于符合中国公开地图要求。

### 10.2 允许的低风险操作

在不改变边界、重要岛屿、地名、比例关系和版图表达的前提下，可在合规底图上叠加：

- 教学点位。
- 经审核的统计分级或流向。
- 不与政治边界混淆的自然要素。
- 明确标注来源与时间的遥感影像。

即使属于低风险操作，仍需完成发布前视觉核对。

### 10.3 进入送审检查流程的情况

出现下列任一情况，主题不能仅凭内部审核直接发布：

- 修改、重绘或概化国界、行政区界。
- 改变重要岛屿、海域、地名或比例关系的表现。
- 使用境外底图替换中国标准地图表达。
- 自制全国性或跨境地图并对外公开。
- 原审图号适用范围、有效性或地图内容发生变化。
- 叠加数据导致边界被遮挡、误读或表达不完整。

### 10.4 地图发布门禁

每个地图主题发布前必须全部通过：

1. 来源在数据源白名单中。
2. 审图号及适用范围已记录。
3. 边界、岛屿、地名和海域表达逐项核对。
4. 图例、比例尺、方向、数据日期和来源可见。
5. 叠加层不会造成版图误读。
6. 离线降级图与在线图一致。
7. 课堂模式没有裁切审图号、南海诸岛或关键图例。
8. 如发生表现变化，已完成送审判断并留档。

## 11. 隐私与未成年人保护

未成年人信息按[《中华人民共和国个人信息保护法》](https://www.npc.gov.cn/WZWSREL25wYy9jMi9jMzA4MzQvMjAyMTA4L3QyMDIxMDgyMF8zMTMwODguaHRtbD9yZWY9aW1i)从严处理。

### 11.1 允许保存的数据

仅允许在浏览器本机保存：

- `geoquest:preferences:*`：字号、减少动态、音效开关等偏好。
- `geoquest:completion:*`：不含身份的主题完成状态和结构化任务进度。
- `geoquest:schema-version`：本地数据结构版本。

所有本地键必须以 `geoquest:` 开头。

### 11.2 禁止保存的数据

- 姓名、昵称、学号、学校、班级或联系方式。
- 自由文本答案、反思文字、聊天内容或作业内容。
- GPS、精确经纬度、家庭住址或精细活动轨迹。
- IP 地址日志的业务留存、广告标识、设备 ID 或指纹。
- 可将不同主题活动关联到同一个学生的信息。

### 11.3 本地数据规则

- 不使用 Cookie。
- 不把本地完成状态上传服务器。
- 首页和设置页提供“一键清除本机数据”。
- 每个主题提供清除本主题进度的入口。
- 本地数据结构升级必须能安全删除旧数据。
- 家乡主题只允许选择县级或更粗尺度，不调用浏览器定位。
- 浏览器缓存属于资源缓存，不得被用作隐蔽的行为追踪。

## 12. 性能约束

### 12.1 基线目标

在常见校园网络和近五年中端设备上：

- 首页和主题首屏的 LCP 目标不超过 2.5 秒。
- 首次可交互目标不超过 3 秒。
- 首页首次传输量目标不超过 1.2 MB。
- 单主题首屏首次传输量目标不超过 2.5 MB。
- 首页初始应用 JavaScript（不含按路由懒加载的地图、图表和主题模块）gzip 后目标不超过 350 KB。
- 单张首屏图片目标不超过 500 KB。
- 主题默认数据快照目标不超过 5 MB；更大数据必须分块并按需加载。
- 主要拖动、缩放和滑动交互目标保持流畅；避免持续超过 50 ms 的主线程任务。

上述目标为发布门禁的默认预算。需要突破时，主题必须记录原因、测量结果和替代方案。

### 12.2 性能实施规则

- 字体自托管并提供系统字体回退。
- 图片使用适当尺寸和现代格式，提供静态占位。
- 主题模块、地图、图表和数据按路由拆分。
- 不在首页预加载全部主题数据。
- 外部服务超时后快速降级，不无限等待。
- 课堂模式优先稳定，不自动播放高成本动画。

## 13. 可访问性约束

目标为 WCAG 2.2 AA。

- 所有核心操作可通过键盘完成。
- 焦点顺序、焦点样式和跳过导航清晰。
- 正文与背景对比度至少 4.5:1；大字号至少 3:1。
- 不只用颜色表达分类、风险、对错或变化。
- 地图和图表必须提供文字摘要或数据表替代。
- ECharts 启用可访问性描述。
- 滑杆提供数值输入或按钮替代。
- 地图拖动提供方向按钮、地点列表或坐标输入替代。
- 支持 `prefers-reduced-motion`，不强制播放动画。
- 不使用可能诱发光敏反应的闪烁。
- 图片有有意义的替代文本；装饰图标对辅助技术隐藏。
- 错误提示不仅改变颜色，并能被屏幕阅读器读取。
- 课堂模式正文建议不小于 22 px，关键标题建议不小于 32 px。

## 14. 校园网络与设备兼容

- 核心流程只访问 GeoQuest 自身域名。
- 不依赖 Google Fonts、公共 CDN、社交媒体嵌入或境外实时接口。
- 外部视频不是核心流程唯一证据；必须有本地图片、文字或图表替代。
- 主题在外部数据请求失败、地图在线服务不可用或带宽较低时仍可完成。
- 页面支持 1366×768 课堂投屏和 360×640 起的移动端。
- 课堂模式针对 16:9 投屏优化，但不能固定为单一分辨率。

浏览器支持基线：

- Chrome、Edge、Safari 的最新两个主要版本。
- Firefox 最新稳定版和 ESR。
- iOS Safari 与 Android Chrome 的当前主流版本。
- 不支持 Internet Explorer。

## 15. 版本与变更管理

### 15.1 版本规则

- 项目约束使用文档版本，如 `V1.0`、`V1.1`。
- 主题内容和交互使用语义版本，如 `1.2.0`。
- 数据快照使用来源版本、覆盖时期和获取日期共同标识。
- 组件接口发生破坏性变化时升级主题或组件主版本。

主题版本变化：

- PATCH：文字、样式、无语义变化的数据修正。
- MINOR：增加非破坏性步骤、数据年份或辅助图层。
- MAJOR：核心问题、主要互动、证据结构或教材映射发生变化。

### 15.2 约束变更

- 修改本文件必须说明原因、影响主题、迁移方案和生效日期。
- 禁止在单个主题代码中创建与本文件冲突的隐性例外。
- 放宽隐私、地图、版权或禁止项必须升级项目大版本并重新评估。
- 工作簿枚举、TopicManifest 枚举和本文件术语必须同步修改。

## 16. 内容审核流程

主题状态固定为：

```text
候选 → 已设计 → 开发中 → 待审核 → 已发布 → 已归档
```

审核记录状态与主题状态分开维护：`unreviewed → initial → approved`，发现阻塞时为 `blocked`。审核记录必须包含所核对象、审核人、日期、证据和结论；状态迁移只能由真实审核行为触发，不能由脚本按主题批次或 MVP 标签批量通过。

进入“待审核”前应完成：

1. 教学审核：核心问题、单一主操作、证据和反思完整。
2. 课标审核：引用精确到文件、PDF 页和印刷页。
3. 教材审核：单元、书内页、PDF 页和原图核对完成。
4. 数据审核：来源、版本、许可、加工和快照完整。
5. 地图审核：来源、审图号、边界和课堂裁切检查完成。
6. 版权审核：所有非原创素材可公开使用。
7. 隐私审核：无禁止采集和持久化字段。
8. 技术审核：性能、可访问性、降级和浏览器测试通过。

不得由“页面能打开”替代内容与合规审核。

- [ ] 使用稳定主题 ID、slug 和 `/topics/:slug` 地址。

- [ ] 核心问题、唯一主操作对象、主要互动、证据产出和反思完整。
- [ ] 探索模式与 `?mode=classroom` 使用同一内容。
- [ ] 课堂主流程 8—15 分钟内可完成。
- [ ] 课后流程无需教师账号或说明才能独立完成。
